## 🗄️ Data Structure (Cloud Firestore Schema)

All notes are stored strictly under the user's isolated subcollection to prevent cross-tenant data access:

### Path: `users/{userId}/notes/{noteId}`

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `id` | `String` | Unique Firestore document ID | Auto-generated by Firestore |
| `title` | `String` | Note title | 1–80 characters (trimmed), non-whitespace |
| `content` | `String` | Note body | 1–2,000 characters (trimmed), non-whitespace |
| `category` | `String` | Note category (`personal`, `work`, `study`) | Enum serialized string |
| `isFavorite` | `Boolean` | Star / Favorite status flag | Defaults to `false` |
| `createdAt` | `Timestamp` | Initial creation time | `FieldValue.serverTimestamp()`, preserved on update |
| `updatedAt` | `Timestamp` | Most recent modification time | `FieldValue.serverTimestamp()`, updated on every save |

## 🔒 Firestore Security Rules

Stored in [`firestore.rules`](firestore.rules):

```javascript
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Multi-tenant user data isolation:
    // Only an authenticated user whose UID matches the path may read or write.
    match /users/{userId}/notes/{noteId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // Explicit deny-all fallback for any other collection or document
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

## 🛡️ Evidence of Access-Control Checks

The security rules enforce three mandatory access control guarantees:

### 1. Owner Access Succeeds
- **Request**: An authenticated user with UID `user_123` attempts to `read` or `write` to `/users/user_123/notes/note_abc`.
- **Evaluation**: `request.auth != null` (`true`) and `request.auth.uid == 'user_123'` (`true`).
- **Result**: **ALLOW** ✅

### 2. User B Access to User A's Note is Denied
- **Request**: Authenticated User B (`request.auth.uid == 'user_B'`) attempts to read or modify `/users/user_A/notes/note_abc`.
- **Evaluation**: `request.auth.uid == 'user_A'` evaluates to `'user_B' == 'user_A'` (`false`).
- **Result**: **PERMISSION_DENIED (403)** ❌

### 3. Unauthenticated Access is Denied
- **Request**: An unauthenticated client (`request.auth == null`) requests `/users/user_123/notes/note_abc`.
- **Evaluation**: `request.auth != null` evaluates to `false`.
- **Result**: **PERMISSION_DENIED (401/403)** ❌

*Note: In addition to the backend rules, account isolation is verified programmatically in our test suite via [`test/unit/user_isolation_test.dart`](test/unit/user_isolation_test.dart), ensuring that when a user logs out, active streams are cancelled and memory state is synchronously wiped before a new user logs in.*

## 🚀 Getting Started

### Prerequisites
- Flutter SDK `3.24.0` or higher
- Android SDK installed (API level 21+)
- Java / JDK 17

### Setup Steps
1. **Clone the Repository**:
   ```bash
   git clone https://github.com/mudasirunar/Personal-Notes-Flutter-App.git
   cd Personal-Notes-Flutter-App
   ```

2. **Install Dependencies**:
   ```bash
   flutter pub get
   ```

3. **Verify Firebase Setup**:
   The project includes configured `google-services.json` (Android) and `GoogleService-Info.plist` (iOS) linked to `personal-notes-app-30e1a`.

4. **Run the Application**:
   ```bash
   flutter run
   ```
